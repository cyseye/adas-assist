# adas-assist v1.0 设计

以 os 为任务协作入口，直接复用根技能、命令、角色、共享规则与标准库工具。仅适配 Codex，不建立独立分发层或自动事件运行时。

## 1. 架构选择

| 方案 | 收益 | 代价与决定 |
|---|---|---|
| 大型自动运行时 | 自动化能力多 | 超出当前轻量范围，不采用 |
| 只使用规则 | 最轻 | 任务与证据依赖人工；作为降级选择 |
| 规则 + 确定性文件工具 | 保留任务闭环，易移植 | 采用；不发展为执行平台 |

```text
用户任务、项目规范、当前授权
                |
       Codex
                |
           os 六模式入口
                |
     执行、真实检查、必要独立评审
                |
       项目已有工具与开发能力
                |
    可选 task.py：状态/声明/文件校验

根 skills/commands/agents/standards：直接按需使用
.agents/skills/：相对软链接发现入口
```

根 `skills/` 是唯一维护源，`commands/` 只路由，`agents/` 提供角色正文，`doc/` 保存设计与验证记录。

## 2. 重点功能与常用模式

| 模式 | 重点行为 | 完成边界 |
|---|---|---|
| direct | 单点执行与相称验证 | 不强建任务文件 |
| managed | 多步计划、执行、验收收束 | 验收对应证据或明确待验 |
| brainstorm | 少量不同候选、反方、取舍 | 不绑外部账号与固定编队 |
| plan | 目标拆解、依赖、产物、验收 | 用户只要计划就不擅自执行 |
| review | 只读审查、缺陷分级 | 不默认修复 |
| recover | 核记录、工作树、证据时效 | 不凭旧 done 直接追认 |

目标拆解、审查修复、长任务分别用模式组合覆盖，不新增重复入口/台账。项目域默认只改当前任务授权范围；内核维护要属于本次请求。模式、工作域、资源预算各管一维，切目录不扩权。规则正本见 [modes](../skills/os/references/modes.md)。

保留核心：路由、目标澄清、规划与候选比较、按授权协作、必要反方/独立复核、证据验收、根因修复、交付与恢复。知识沉淀、原始经验参数与外部扩展不进入本版默认链。

初始化是独立入口 `$os init`，不增加任务模式；先核项目指引、工作树与宿主接入，明确要求时增量补指引。由当前会话按本地契约只读检查 Git、适用指引、入口及项目验证命令；真实宿主发现另验。契约见 [initialization](../skills/os/references/initialization.md)。

## 3. 单任务状态与数据设计

已有任务记录优先，不强制替换项目工具。没有既有载体的复杂任务可选人工 TASK.md 或可选 CLI，单任务只保留一个状态源；CLI 检测到同目录人工 TASK.md 会拒绝创建第二状态。

CLI 单 JSON：`.adas-assist/tasks/<slug>/task.json`。schema=1，包含目标、授权范围、模式、状态、revision、显式输入文件、验收项、声明证据、评审来源、阻断/取消原因和下一步。

状态 planned→active→done，active↔blocked；done 可说明原因 reopen，未终态可附依据 cancelled。写锁覆盖读、校验与原子替换；所有内容校验先于保存。status 只读，证据漂移只报告，不静默改状态。锁冲突直接拒绝，崩溃遗锁先检查所有者再人工恢复。

finish 要求全部验收声明 passed、证据存在且 SHA 一致、声明时显式输入的内容与范围未变；要求独立复核时还要当前通过的来源声明。工具不运行检查、不认证评审身份，不证明陈述真实/业务正确。input 范围不完整、环境或外部服务变化仍需人工判断。

实际验证后立即记录证据，不能补录旧检查给新代码背书。必要的生产/发布/破坏性动作授权、验证回退与独立复核在执行前完成，不能移到 finish。具体字段和操作见 [execution](../skills/os/references/execution.md)。

## 4. Codex 入口与根资产

`.agents/skills/` 中的技能及辅助目录通过相对软链接指向根 `skills/`，os 与其他技能一致。技能入口使用 name/description frontmatter，按模式读取 references；agents/openai.yaml 只提供 UI 元数据。无需安装、更新或卸载工具，不维护副本和回执，不修改用户全局配置。

commands 与角色 Markdown 不等于宿主原生注册。实际委派需要当前工具支持及本次授权；独立审查不得由主控自审冒充。链接正确、技能发现、模型执行和业务成功分别验收。

## 5. 模型、token 与周期设计

模型职责：确定性检查优先脚本；常规执行选足够可靠的可用模型；关键架构/风险由独立强审查；疑难经补证与多轮针对性评审仍矛盾才升级。不给固定型号比例或经验最优参数，不让资源不足删掉必要验收；实际模型/用量不可读则标未知。

省流在消费点执行：先索引后定向读；按模式读参考；短委派与结果指针；长日志落盘；新变更未影响的检查不重跑；接力保留目标/授权/决策/未决/下一步。不移植未公开压缩变量、缓存阈值、账单或账号策略。规则见 [resources](../skills/os/references/resources.md)。

周期规则仅给手动检查和责任契约：改资产后运行相关测试、接力前核任务、活跃维护期可选周检、宿主升级后 smoke。自动化需另有明确授权、负责人、频率/时区、超时互斥、结果和暂停删除办法；本版不注册调度器。规则见 [periodic](../skills/os/references/periodic.md)。

## 6. 维护与交付边界

任务状态行为测试位于 skills/os/tests；共享契约检查覆盖文件分类、链接、Python/JSON和角色消费者。迁移不改变 task.py 状态协议；分发专用安装器、导出清单及测试不再保留。

工作分支为 v1.0，不代表正式发布完成。Codex 新会话发现、完整行为、用量收益与发布许可仍分别待验，见 [计划](GOVERNANCE-PLAN.md)。
