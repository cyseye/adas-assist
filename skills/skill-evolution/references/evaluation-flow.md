# 技能改进执行流程

1. 读本次明确的目标、问题和用户反馈，按 authoring-checklist.md 检查正文。
2. 按 gate-rules.md 和共享 evolution-discipline 判断范围、根因与风险；没有可重复测试集则限本次修复，不签效果改善。
3. 需要方案裁决时，主控核证据后给 proposer 事实摘要，再将候选 JSON 交 critic、合并结果交 finalizer。角色输入、预算与落盘职责以共享 pcf-execution-flow.md 为准，不给禁止读源文件的角色只传文件路径。
4. 按 worktree-sop.md 隔离改动。原工作区已有在途修改时核实际基线，不覆盖或擅自提交。
5. 回归同一输入集，保留正常/异常题面及失败；行为效果比较再加至少一个换输入、执行体或判据的复测。
6. 改善、下降、持平或证据不足分别记录到 EVOLUTION.md。下降时提出有依据的回退；持平默认不增加机制；无数据不报告改善。
7. 重大决策由 decision-record 维护；清理按 cleanup-rules.md，只处理无后续消费者的本批产物。

本流程由当前任务负责人显式执行，无评估引擎、自动日志、调度或缺失脚本依赖。
