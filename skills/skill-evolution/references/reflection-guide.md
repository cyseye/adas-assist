# 定期反思流程（「进化的进化」）

## 触发条件（明确触发，不自动）

- 用户主动说「反思进化」
- 主 agent 日历提醒（每周/每月，可配置）

> **不依赖进化次数**——克制模式下可能长期无进化，避免「不进化→不反思」恶性循环。

## 反思维度（4 个）

| 维度 | 核心问题 |
|------|----------|
| ① 近期进化有效性 | metrics 真提升了吗？还是数据波动？ |
| ② 方向是否偏 | 过度优化某类 / 忽略其他类问题？ |
| ③ 标准是否需调整 | 门控阈值 / 不动清单需收紧或放松？ |
| ④ benchmark 是否过时 | 现有基准覆盖当前主要问题吗？有新问题类型需加入？ |

## 反思步骤

1. **收集**：读各 skill EVOLUTION.md（最近 3-5 轮）
2. **评估**：按 4 维度 PCF 分析，产出发现
3. **记录**：写 `REFLECTION.md`（每条：日期/范围/发现/调整建议/是否反馈）；读取时先用 `offset=0,limit=8` 读摘要头，深读用 `offset=8`

## 反馈闭环

```
反思建议 → PCF 确认 → 更新对应 skill 的 metrics / 不动清单
                                       ↓
                            下一轮进化验证（metrics 是否真提升）
                                       ↓
                            记入下一轮 REFLECTION.md（闭环）
```
