# 多轮迭代 Delphi 协议

> decision-consensus 的执行细则。主控按本协议编排 pcf-proposer 多轮提案，实现经典 Delphi 的「多专家并行独立 + 迭代收敛」。术语对齐 SKILL.md「术语」表。

## 角色与视角

### 默认视角集（5）

| 视角 | 关注点 | 提问倾向 |
|------|--------|----------|
| 架构 | 可扩展性 / 耦合 / 技术债 | 是否过度设计？组件边界？ |
| 安全 | 攻击面 / 权限 / 数据泄露 | 信任边界？越权风险？ |
| 性能 | 延迟 / 吞吐 / 资源占用 | 瓶颈在哪？峰值压多少？ |
| 用户 | 易用性 / 体验 / 可达性 | 谁用？怎么用？学习成本？ |
| 成本 | 开发 / 运维 / 许可 / 人力 | 一次性还是持续？ROI？ |

### 视角裁剪规则

- 默认启用全部 5 视角（每视角 spawn 1 个 pcf-proposer）
- 可按分歧性质裁剪，但**至少保留 3**（少于 3 无法形成有效共识，触发 SKILL.md 降级策略）
- 裁剪示例：纯技术分歧 → 可去「用户」；纯成本分歧 → 可去「安全/性能」
- 视角集在 R=1 前确定，**跨轮不变**（保证收敛度量可比性）

## 匿名化规则

### 为何匿名

消除权威偏差与从众效应（proposer 互相可见时强势视角压制弱势视角，共识失真）。

### 如何匿名

- **proposer 间隔离**：每轮每个 pcf-proposer 独立 spawn，prompt 仅含「分歧上下文 + 本视角职责 + 上轮反馈（R>1 时）」，**不含其他 proposer 的原文或身份**
- **主控汇总去标识**：主控汇总时按视角聚合（「架构视角认为…」「性能视角认为…」），不暴露「哪个 proposer 说了具体某句」的归属
- **轮间反馈去标识**：R 轮 summary 反馈给 R+1 轮时，只公布「共识点」与「差异点」，不指明各点来自哪个视角

> 工程化折中：去标识是相对的——视角名本身是标签（架构/性能等），但「视角内具体措辞归属」被抹平。这与教科书式完全匿名略有差异，是务实的工程折中，兼顾可追溯与去权威。

## 反馈格式

### summary → 下轮 proposer 的注入内容

R 轮结束、未收敛时，主控生成 summary 并构造 R+1 轮各 proposer 的 prompt，注入：

```
【分歧上下文】{原始问题描述 + 各方立场}
【你的视角】{视角名} —— 关注：{该视角关注点}
【上轮反馈（R={R-1}）】
  共识点（各方已一致，不再讨论）：
    - {共识点1}
    - {共识点2}
  差异点（仍存分歧，请在此聚焦收敛）：
    - {差异点1}：{各方立场简述，去标识}
    - {差异点2}：{各方立场简述，去标识}
【你的任务】基于上轮反馈，从{视角名}视角重新提案，尝试在差异点上收敛；
          必要时可调整原立场，并说明调整理由。
```

### 反馈约束

- **不直接引用其他 proposer 原文**（仅转述为去标识的立场摘要）
- **聚焦差异点**（共识点不再讨论，避免重复迭代浪费）
- **鼓励调整立场**（明确告知可改变立场，这是迭代收敛能收敛而非僵持的关键）

## 轮间信息流

```
R=1（首轮，无反馈）
  各视角独立首提案 → 主控汇总 → summary1（convergence_score1）
  ↓ 未收敛（见 convergence-rules.md）
R=2（注入 summary1 反馈）
  各视角基于反馈再提案 → 主控汇总 → summary2（convergence_score2）
  ↓ 未收敛且 R<max
R=3（注入 summary2 反馈）
  各视角基于反馈再提案 → 主控汇总 → summary3
  ↓ R≥max → 强制收敛
收敛后 → pcf-critic（可选，残余≥2 时）→ pcf-finalizer
```

### 首轮（R=1）特殊性

- **无反馈注入**：各视角仅凭分歧上下文首提案，反映各视角原始立场
- **首提案去标识后即作为收敛度量起点**，后续轮次的 convergence_score 以此为基线
