# Socratic 提问维度（需求场景）

> 把模糊需求拆成五个正交维度逐个澄清，避免遗漏和重复提问。信息密度优先：每问必有明确目标。问法纪律（收敛信号/提问四条/批次上限）见公共件 `~/.claude/skills/_shared/socratic-inquiry.md`，本文件只持需求场景的维度内容。

## 五维度

### 1. 目标（Goal）
要解决什么问题？成功的样子是什么？
- 典型问题：
  - 这次要解决的核心问题是什么？（一句话）
  - 做完之后，什么事情会变得不同？
  - 谁是受益者？他们如何感知到「做好了」？
- 收敛标志：能用一句话说清「做什么 + 为谁 + 带来什么改变」

### 2. 边界（Boundary）
包含什么、不包含什么？范围在哪里切断？
- 典型问题：
  - 哪些明确在范围内？哪些明确不在？
  - 本期做 vs 后期做 的分界在哪？
  - 是否依赖前置工作或并行的其他工作？
- 收敛标志：包含 / 不包含清单可枚举，无「待定」大块

### 3. 假设（Assumption）
隐含前提是什么？哪些假设错了会推翻方案？
- 典型问题：
  - 这个需求成立的前提是什么？
  - 如果某个前提不成立，方案哪部分会失效？
  - 有没有未验证的技术 / 业务假设？
- 收敛标志：关键假设已识别并按假设协议记录

### 4. 约束（Constraint）
有哪些硬性限制？
- 典型问题：
  - 技术栈 / 兼容性 / 性能 / 安全硬约束？
  - 时间 / 人力 / 资源约束？
  - 不能动的部分（已有系统、表结构、API 契约）？
- 收敛标志：约束清单明确，尤其「禁止修改」项已标出

### 5. 验收（Acceptance）
怎么判断完成了？
- 典型问题：
  - 完成的可观测标准是什么？（非「用户满意」而是具体可验证）
  - 有没有必须通过的用例 / 场景？
  - 验收由谁、在什么环境做？
- 收敛标志：验收标准可量化或可演示
