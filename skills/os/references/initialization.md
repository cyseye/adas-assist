# 初始化与 Codex 适配

`$os init` 是 os 的项目初始化检查入口，不是任务模式，不创建 task.json，也不执行开发任务。仅传 init 时只读检查；明确要求“初始化/完善项目指引”时，先核现有内容，再在本次授权范围内增量补充。它不注册或覆盖宿主 `/init`；宿主原生命令的可用性和行为以当前客户端为准。

若宿主将 `/init` 请求交给 agent，按本契约完成项目检查；需要生成指引时增量维护 AGENTS。客户端若直接消费该命令，本仓规则无法拦截；可明确使用 `$os init` 或要求读取本规则。

## 检查顺序

1. 核当前目录、项目根和 Git 状态；无 Git 时如实记录，不自动 git init。先读适用的项目指引、README 及相关设计，子目录任务还要检查该路径的嵌套指引。保留在途修改。
2. Codex 检查适用的 AGENTS 指引（包括 AGENTS.override.md）；父级/用户级指引、覆盖顺序与实际载入路径由当前会话核实，不宣称已完整扫描宿主规则。
3. 从仓库根检查 skills/os/SKILL.md 与所需参考文件，确认 .agents/skills/os 相对软链接指向该维护源。其他技能与辅助入口按本次需要检查；缺失或目标错误只报告，不覆盖未知文件。没有独立安装或初始化工具。
4. 分别报告维护源、链接、宿主发现与实际命中。CLI 不存在可能是应用宿主，不直接判定无法使用；文件可读不代表已发现。
5. 从项目真实文档和配置核实最小验证命令、依赖、工作目录与任务记录位置。目录或配置存在仅是候选，不代表测试运行；不为探测安装依赖、执行未知脚本或加载 hooks。
6. 按既有入口核共享规则/角色路由、任务记录以及项目 memory/决策索引。只读必要索引和本次相关正文，缺件报告；不搬运全局资产，不创建空记忆或 ADR，不把文件存在当成自动召回或角色注册。
7. 实际使用技能时记录命中的 SKILL.md 路径。新会话核技能发现、help、init 只读、plan +v 不实施；受环境限制则标待验。文件一致、CLI 可找到不能替代这些行为证据。

## 增量完善项目指引

优先编辑现有 AGENTS.md 的相关段落；保留用户规则及其他任务修改，不整份重建，不将整个共享规则库复制进去。存在覆盖指引时先确定实际生效文件，避免补入不被消费的文件；不直接改用户级配置。

按真实项目填写以下内容，未核实则列为待补，不能写成成功配置：

- 项目目标、目录/维护源、入口与运行数据边界。
- 最小改动、Git 在途保护、不擅自提交/推送/发布。
- 构建/检查/测试的真实命令与运行目录，实际检查、静态判断、未验证分别报告。
- os 的实际入口及按需读取路径；已有复杂任务记录与恢复方法，避免第二套状态源。
- 宿主边界：模型由宿主选择；角色 Markdown、后台调度与记忆不会因读取文件自动注册；独立评审需真实独立来源。

报告用“检查项 / 状态 / 文件或命令证据 / 下一步”，状态可为已核实、需处理、未验证。缺非必要条件不阻断无关工作；缺必要授权或验证能力就保留对应待验项。`init +v` 只复核初始化结果，不启动其建议的开发任务。

`task.py init <slug>` 仍是创建单个任务状态的文件工具，与项目初始化不同。
