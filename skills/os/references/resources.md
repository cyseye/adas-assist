# 模型分工与 token 预算

## 模型按职责选择

| 职责 | 选择依据 | 升级条件 |
|---|---|---|
| 确定性采集/校验 | 脚本、编译器、项目检查 | 脚本无法解释语义时交模型 |
| 常规执行 | 当前可用且足够可靠的模型 | 复验失败或出现关键不确定性 |
| 关键审查 | 能独立检查核心结论的强模型/审查者 | 核心架构、接口或重大风险 |
| 疑难兜底 | 已有补证与针对性评审仍矛盾时再选更强能力 | 写清已试路径与未决点 |

不硬编码型号、账号、配额比例或“最佳”成本结论。不为凑比例降低必要审查；不因措辞复杂就升级。模型实况不明标未知，不把角色意图写成实跑型号。资源不够先缩小可并行范围，不能删除必要验收。

宿主原生选择由用户/操作者配置；skill 只能建议职责、给出委派契约，不保证切换当前会话模型。新增外部付费调用仍遵守当前授权。

## 省流规则与消费时机

- 开工：先索引与定向搜索，再读命中文件；按任务模式读 references，不整库注入。
- 工具输出：长日志先存文件，回传结论、错误和证据位置；保留完整报错可访问，不能把被截断输出当完整扫描。
- 委派：只传必要路径与验收，短回传结果/证据/限制；没有独立任务收益就不并行。
- 多轮：沿用同一任务契约，失败后定向复验，已通过检查仅在新变更影响时重跑。
- 接力：保留目标、授权、决策、未决、下一步；可重建输出只留指针。
- 缓存：规则短且稳定，不为省 token 动态改写宿主系统配置；不依赖未公开环境变量或压缩阈值。

预算用“预计读取范围、输出长度、最大轮数/时间、并行数”表达，由任务负责人在开始与追加资源时消费。能读取真实 token 用量时记来源和口径；无法取得就写未知，不凭字数推算账单，也不承诺固定节省比例。
