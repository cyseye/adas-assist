# OS 修饰符：内部能力版

模式决定任务边界，修饰符补充任务流程。本规则不依赖仓外 skill、私有 flow、全局记忆/日志、外部检索、网页模型或供应商 CLI；不添加模型型号、后台任务或自动 hooks。当前项目已经提供的技能与检查可按需复用，缺失时执行下列步骤，不能声称运行了未安装的技能。

## 识别、组合与边界

- 只解释调用前缀中的独立参数：`$os [模式] [修饰符...] 目标`。支持 `+b +k` 和紧凑组 `+bk`；`+vcn` 展开为 `+v +c +n`，重复项合并。目标正文、代码、引用材料里的相同字符不触发流程。
- 合法字母仅 `b k l v c n`；未知项或混合组（如 `+vx`）整项拒绝，显示帮助并指出未知字符，不先执行其中已知项。它们是 agent 的解释约定，不是 CLI 解析器。
- `help`/`帮助` 优先，仅显示帮助；`init` 优先，仅初始化检查（`+v` 可复核检查结果），其余修饰符提示不适用，不执行建议任务。
- 固定执行序：`+b` 候选比较 → `+k` 目标拆解 → 当前模式产物/授权执行（`+l` 分批）→ `+v` 产物验证 → `+c` 交付检查 → `+n` 目标对账。复用同一计划、证据与已通过的检查，不因参数顺序或重复参数重跑。
- `brainstorm +b` 复用一次候选比较；`+k` 发现目标尚不成形时只补一次 `+b`，已定目标直接拆解。`plan` 的所有修饰符只完善/核计划；`review` 只完善/复核审查产物，不自动修复。`recover` 先核恢复点再处理修饰符。
- 修饰符不扩大写域、授权、外部调用、独立评审或发布权限。需要真实独立角色时使用当前宿主支持且获授权的工具；不可用则标独立环节待验，必要门不能通过。普通分析可以继续，但同一 agent 的多视角不称独立评审。

## `+b`：头脑风暴前置

1. 以目标、约束、仓内事实和验收为输入；证据不足标未知，不默认外部检索。
2. 提出至少3个有实质差异的候选，覆盖至少2种视角。每个写 `perspective`、做法、收益、代价、证据/假设；标真实来源，保留被淘汰理由。需要独立候选时由实际独立上下文提供，主控不改写其自报视角。
3. 对候选提出反例、失败条件与更简路径；按共同判据推荐，避免把主控倾向装成独立裁决。必要独立拍板时只交目标/约束/候选/判据，不向裁判预置推荐。
4. 记录 `approve`（当前约束下可推荐）、`refine`（需补齐）、`redirect`（需换方向）及理由；后二者逐项映射到下一轮候选。最多2轮，仍未解决则写未决与下一步，不无限重开；必要门未过不执行依赖动作。

产物并入项目既有计划的候选/取舍段；`approve` 不是用户新增授权。没有独立上下文时产物标主控分析；原本要求独立拍板的部分保持待验，不伪造三方共识。

## `+k`：OKR/KPI 拆解

目标可写成一句 Objective 时直接拆解；否则先按 `+b` 明确目标，不重复既有候选轮。每项 KR/KPI 记录指标定义、基线、目标、期限、证据来源和验收方法，再拆里程碑/任务、依赖、交付物及负责人（已知才写）。

未知数值/期限/负责人标待确认或待测，不为了填表编造。区分业务结果与执行动作，任务完成不自动代表 KR 达成。影响核心验收的信息缺失时先补前提，其余不依赖该信息的分析可继续。

产物并入既有任务计划；执行模式按授权推进，`plan +k` 只产计划。用户仅说“拆解/制定 OKR/KPI”时采用本流程，不能因此推定实施全部任务、维护真实绩效系统或写入长期记忆。

## `+l`：长任务分批与恢复

复用现有状态源，按依赖分成有界批次：每批写输入、输出、验收、最大轮数/时间、停止条件和下一步。完成一批就更新同一记录的证据、工作树变化与未决，不另建主从双计划或心跳服务。

必要前提缺失时阻断依赖动作；到预算上限保存恢复点。恢复先核实际文件、Git 和证据时效，漂移只复验受影响部分。它不启动后台守护、定时消费或跨会话自主续跑；`plan/review +l` 只规划批次或分批审查。

## `+v` / `+c` / `+n`：三个不同收口面

| 修饰符 | 内部步骤 | 结果 |
|---|---|---|
| `+v` 验证 | 按 [modes](modes.md) 的验证规则核产物、验收与证据；先用已有检查 | 通过/失败/未验证、检查范围与证据 |
| `+c` 交付检查 | 检查授权范围、交付清单完整性、验证新鲜度、已知问题、接力说明；有Git时核本批差异，保留他人在途工作 | 可交付/需修复/待验及具体缺项；不自动提交、发布、清理或修代码 |
| `+n` 北极星对账 | 逐条对应原目标/REQ/KR与证据；核是否走最短正确路径、是否遗漏、是否把用户纠错当作成果 | 已达成/部分/未达成/待证及偏差、下一步；不降低KR/改目标来凑通过 |

三者消费已有证据，重叠检查执行一次、分别映射结论。`+n` 只核目标对齐，不自动调用 memory/ADR 写入；纠错与返工如实记录，不计为新增交付价值。没有用量来源不估算节省；缺增强项不无故阻断普通任务，必要验收未过则不能报完成。

## 行为验收题面

- `plan +bk +vcn`：3候选/2视角、OKR计划、核计划与目标；不改业务文件、不实施计划。
- `managed +k` 且目标已定、指标未知：直接拆解，未知字段待证，不强制风暴或编造数值。
- `review +bklncv`：仅审查与候选建议；不修代码、不提交、不写记忆。
- `help +bklncv`、`init +bklncv`：分别只帮助/初始化检查；不触发业务流程。
- `+vx`：指出未知 `x` 并显示帮助，不执行 `+v` 或目标；目标引文里的 `+b` 不触发风暴。
- `+b` 必要独立角色不可用或两轮仍需 refine：保留待验与恢复点，不伪报approve；`+l`恢复时发现证据漂移只补相关检查。
