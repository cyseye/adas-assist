# 生命周期信号与量化门槛

> 判断「是否需要新增 / 拆分 / 合并 skill」的信号清单与门槛。设计参考 skill-evolution 的双阈值门控：默认不动，信号触发，量化评估，克制优先。稳定胜过完美。

## 信号归类（三正交维度）

| 信号类型 | 含义 | 典型来源 |
|----------|------|----------|
| 新增 | 现有 skill 体系覆盖不了的重复模式 | 同类 prompt 反复出现、新场景与现有触发条件冲突 |
| 拆分 | 单 skill 承载过多职责 | 执行超时、多触发条件、多产物、文档过长 |
| 合并 | 多个 skill 职责高度重叠 / 路由混淆 | 触发条件交叉、用户反复误路由、产物雷同 |
| 无 | 现有体系可覆盖 | —— |

## 新增信号（考虑新建 skill）

| 信号 | 说明 |
|------|------|
| 同类 prompt 重复 ≥3 次 | 没有现成 skill 覆盖，每次靠主 agent 临场处理 |
| 现有 skill 无法覆盖新场景 | 触发条件 / 产物类型都不匹配 |
| 新场景与现有 skill 触发条件冲突 | 容易被错误路由 |

## 拆分信号（考虑拆分现有 skill）

| 信号 | 说明 |
|------|------|
| skill 执行超时 / 上下文超限 | 单 skill 承载过多职责 |
| 单 skill 含 ≥2 个独立触发条件 | 职责边界模糊 |
| 产物类型 ≥2 种且无关联 | 一个 skill 出多种不相关产物 |
| SKILL.md 超 150 行且难精简 | 详细规则过多，应拆分下沉 |
| 单个 reference/registry 文件超 400 行行动线 | 资产粒度膨胀（阈值见 skill-design.md「资产三分法与大小阈值」），按处置分级评估拆分/瘦身，可判不动 |

## 合并信号（考虑合并多个 skill）

| 信号 | 说明 |
|------|------|
| 触发条件交叉重叠 | 用户/主 agent 反复在两个 skill 间误路由 |
| 产物类型雷同且互补 | 两个 skill 产出可被单一 skill 统一覆盖 |
| 合并后 SKILL.md 仍 ≤150 行 | 合并不至于制造巨型 skill |
| 已有 skill 拆分后长期低频 | 拆分出的子 skill 调用频次极低，徒增维护 |

## 量化门槛（须同时满足才动手）

对齐 skill-evolution 的双阈值判定，避免偶发信号误触发。

**新增**：
- 复用率：新场景在 ≥2 次任务中重复出现
- 收益量化：能定义可观测效果指标（产物分 / 覆盖率等）
- 不重叠：与现有 skill 触发条件可清晰区分

**拆分**：
- 拆后各 skill 独立可测（各有自己的 metrics）
- 拆后 metrics 不降（拆分不应牺牲质量）
- 触发条件清晰（拆分后无路由歧义）

**合并**：
- 合并后触发条件单一清晰（消除误路由）
- 合并后 metrics 不降（用被合并 skill 的 metrics 验证）
- 合并收益 ≥ 维护成本下降（≥2 个 skill 减为 1 个，且无职责塌缩）

## 不动清单（明确禁止动手）

| 场景 | 理由 |
|------|------|
| 单次偶发需求 | 样本不足，不足以建 / 改 skill |
| 可用现有 skill 组合覆盖 | 组合优先于新建 |
| 改动风险 > 收益 | 克制优先，稳定胜过完美 |
| 无法定义可量化指标 | 无指标则无法评估，不适合建 skill |
| 仅为"美观/整齐"合并 | 合并须消除真实路由混淆，非为收纳 |

## 决策表

| 信号 | 门槛评估 | 动作 |
|------|----------|------|
| 新增信号 + 门槛满足 | 复用率 / 收益 / 不重叠均达标 | 建议**新增**（写待确认项，走 PCF，等用户确认） |
| 拆分信号 + 门槛满足 | 拆后可测 / 不降 / 清晰均达标 | 建议**拆分**（写待确认项，走 PCF，等用户确认） |
| 合并信号 + 门槛满足 | 单一清晰 / 不降 / 收益达标 | 建议**合并**（写待确认项，走 PCF，等用户确认） |
| 信号出现但门槛不满足 | 复用率不足 / 无指标 / 拆后降 | 不动，记 memory 待积累 |
| 无信号 | 现有体系可覆盖 | 不动 |

> 建议动作「不自动执行、等用户确认」单源=SKILL.md 执行流程表 Step 8，此处不复述。
