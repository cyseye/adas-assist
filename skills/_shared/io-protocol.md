# I/O 协议

预算值见 [io-budgets](io-budgets.json)，由 io-governance 维护。规则由本次任务负责人消费，不实现工具拦截或自动注入。

## 1. 读取与预算

先索引后定向读，长输出保存为任务产物后分段读取，保留完整报错与反例。预算受当前宿主和项目指引约束；缺少实际用量时标未知，不估算账单。

## 2. 委派输入

按 spawn_prompt 预算传必要目标、文件、写域和验收。超长材料用受限文件路径；小输入可内联。PCF 三角色按 [交接协议](pcf-execution-flow.md) 使用限长摘要/JSON，源证据由主控或独立审查角色核验。

## 3. 回传与产物 schema

通用回传：`{status, file_path, read_files, 关键计数, risks}`。审计/核验类必须列实际读取文件；长度按 subagent_return 预算。报告命名为 `{skill}.round.{N}.*.json` / `report.{skill}.final.json`；特化登记在 review-gate-skeleton。

PCF 三角色只返回各自严格 JSON，不加通用包装；主控校验、原样落盘，记录真实来源后交下一步。JSON 失败由原角色重发一次，仍失败停止交接并保留待验。

## 4. 长输出与恢复

只回传结论、计数、首错和产物指针，不把截断当作完整证据。子任务到预算上限保存结果与未决；可摘要的独立任务才接力，审查/裁决不得拆散关键证据。

状态查询尽量合并，等待使用当前工具支持的通知机制；无后台授权不启动服务。限流有界重试并降并发，不绕过配额。

## 5. 审计

io-governance 按实际输入/回传核覆盖分母、命名和预算。没有日志为 no_data，不宣称零违规；预算读取失败不在脚本内补默认常量。
