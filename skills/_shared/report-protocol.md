# 汇报协议

结论先行，按任务规模保留必要细节；简单问题简答。进度只报告新发现、异常和影响下一步的决定。

## 交付内容

- 说明完成的范围、实际变化和仍未完成的事项。
- 区分实际运行、静态检查与未验证项；结论附本地文件或命令证据。
- 检查结果给出读数与分母。无数据标为 no_data，不把扫描无信号写成语义通过。
- 关键风险、必要用户裁决和下一步明确列出；不把历史结论作为当前实测。

复杂任务沿用项目既有状态载体，记录目标、约束、已完成、证据、决策和待验项。没有变化时不重复大段汇报；不建立自动水位、周期汇报或额外全局台账。

## 文件与并发

长输出先保存为本次任务产物，再分段读取；保留完整报错和反例，以可点击路径引用。文件路径与命令应能在当前仓库定位。

多个任务不得同时读改写同一状态文件；由主控串行更新或划分独立写域。确需脚本原子替换时，可用 [shared_state](scripts/shared_state.py) 的 atomic_write，并显式配置授权根。原子替换不提供并发锁，也不能保证并发读改写正确。
