# PCF 文件交接协议

角色正文使用根 agents/ 的 pcf-proposer、pcf-critic、pcf-finalizer；输出字段以各角色为准。本协议定义交接，不注册宿主角色或切换模型。

1. 主控记录问题、约束、候选空间、验收与证据路径。创建本次专属 `.build/<任务>/`，不混用其他批次。
2. 主控核原始证据，按各角色输入契约提供事实摘要或结构化 JSON；proposer 提候选，critic 指出反例与风险，finalizer 裁决。角色返回严格 JSON，主控校验并原样落盘，产物可读后才交下一步。
3. 必要独立评审必须来自不同执行上下文或真实外部审查者；同一会话自演只标分析，不得签独立共识。工具/授权不具备时明确未完成独立环节。
4. PCF 三角色使用各自定义的摘要/JSON 输入；审查角色另接受限的源文件路径独立核证。主控串行协调并负责写入，子角色不继续派生。超过角色输入限额或通用预算时先缩减决策输入，无法保真则停止交接。
5. 任一输出缺失、JSON 不合法或不符合角色 schema，停止交接并重试一次；仍失败输出待验与恢复点，不产生假裁决。
6. 裁决不能放宽用户授权，不能接受未处置 must-fix。具体决策空间以调用方 review-gate 协议为准。

## 辩论 history 持久化

`debates.md` 每轮追加：轮次/问题、各角色实际来源、候选文件、critic 文件、finalizer 文件、已选与落选理由、未决风险与下一步。缺少某步如实写未运行，不补造历史。共识轮次和收敛计算仍以 decision-consensus 的 references 为准。
